# AlatyrCore 0.1.0-alpha.93

Framework `0.1.0-alpha.93`, adapter schema `76`, target templates `88`.

## Changes

- Routine framework comparison resolves an explicit installed commit instead
  of treating an advanced or dirty tooling checkout as the installed baseline.
  Upgrade assessment explicitly selects the candidate role. Historical schema
  and template comparison prefers the target's exact pin, with no fallback for
  an invalid explicit pin and no automatic fetch, checkout or target update.
- Optional source helper `publish-task` validates a separate active-model draft,
  derives its projection and updates one registration under the existing writer
  lock and conflict-preserving transaction. It refuses closed/shared models,
  stale bindings and unsafe runtime paths; pending proof stays pending. This is
  local support authoring, not Git publication or task acceptance.
- Framework-upgrade descriptors reference existing inspection and completion
  validation entrypoints. Schema-76 validation checks the binding, and context
  plans expose digest-bound command prefixes without executing them. Auxiliary
  checks remain useful but cannot establish final acceptance.
- Optional source helper `prepare-worker-context` measures and freezes visible
  prompts, bootstrap, packet metadata and selected files before dispatch.
  Conditional expansion retains the prior allocation and sibling reservations.
  `prepare-worker-result --context-preflight` verifies the observed context
  against that allocation. No automatic dispatch, provider-native hard cutoff,
  semantic acceptance, or measured billing improvement is claimed.
- No rule IDs were added or removed. Existing canonical model, projection,
  approval, closure, resource and finalization checks remain authoritative.
- Portable CI also runs the new source-binding, active-task, routing and worker
  preflight regressions on Windows and macOS, including shared write safeguards.

## Required Target Actions

1. Preserve target facts, active work, unresolved evidence, local deviations,
   approvals and frozen historical witnesses. Do not modify product behavior
   to make the adapter pass.
2. Record or verify the installed source commit from actual evidence. Supply
   locally available history for exact baseline comparison. Keep candidate
   comparisons explicit; legacy unpinned comparisons remain labeled as such.
3. Reconcile framework-upgrade `validation_entrypoints` to `adapter-health` for
   inspection and `current-change` for completion. Replace workstation-specific
   wrapper source selection with the canonical delegate route where applicable.
4. Prefer canonical active-model derivation over hand-edited projections.
   Review drafts, preserve unresolved obligations and use explicit local writes;
   closed-task retention and final acceptance remain separate operations.
5. For delegated work, prepare bounded visible context before giving it to a
   worker, account for all allocated workers and verify observed artifacts.
   Keep work local if context delivery cannot be measured reliably.
6. Refresh affected generated support through the canonical finalizer and run
   strict target-owned acceptance with the current bindings. This source change
   does not update any installed project automatically.

## Limits

Source pins establish identity, not trust or business correctness. Cooperative
transactions cannot make arbitrary editors participate or provide multi-file
filesystem atomicity. Preflight covers supplied visible artifacts, not hidden
provider context or unobserved actions. No performance or cost percentage is
claimed; eligible small tasks retain their existing lightweight route.
