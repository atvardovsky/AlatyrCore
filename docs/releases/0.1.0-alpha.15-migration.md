# Alatyr Release Migration Report

This reviewed report compares the nearest reachable tagged source baseline
`v0.1.0-alpha.3` with the source tree prepared for `0.1.0-alpha.15`.
Migration reports for intervening `0.1.0-alpha.4` through
`0.1.0-alpha.14` remain part of the evidence chain. This report is source
evidence, not approval to modify a target repository.

## Adapter Contract Impact

- Framework version changed because lifecycle and dependency rules now carry
  stronger machine-checkable release and discovery requirements.
- Adapter schema version changed because enabled dependency-knowledge policies
  must type each locator as `native-package-metadata-key`.
- Target template version changed for the dependency policy, gate, flow, and
  generated bootstrap evidence.
- Category routing owners and per-rule canonical semantic owners are now
  represented separately. `ALATYR-SAFETY-002` remains canonically owned by
  `framework/prompt-injection.md`.
- Source release validation now covers the triggering tag, every shipped schema,
  and the exact committed migration-evidence contract tree.
- Every committed captured conformance run is registered and validated by the
  canonical source profile.

## Migration Action Hints

- For enabled dependency knowledge, replace any adapter-style metadata locator
  with an exact key or key path in the declared native package manifest and set
  `metadata_locator_kind` to `native-package-metadata-key`.
- Re-render installed routing evidence after adopting target template version
  `15`.
- Keep category routing documents distinct from the canonical owner named by
  each rule registry entry.
- Release maintainers should regenerate and review schema-aware migration
  evidence and record the checked contract-tree hashes.
- Register committed conformance runs with their exact expected fixture set.

## Required Target Actions

- Run `recheck-after-framework-update` before adopting the new framework files.
- If `dependency-knowledge` is enabled, migrate every package source to the
  typed native metadata locator contract before synchronization.
- Run the portable target adapter validator and target-owned checks after the
  template migration.

  and package facts; source placeholders must not replace active target state.

  bridge loading requires new evidence.

## Residual Risks

- A typed locator records the discovery mechanism but cannot prove that the
  selected native metadata key is strategically correct for a target ecosystem.
- Contract-tree hashes prove exact bytes and scope, not the semantic correctness
  of the reviewed migration narrative.
- Static assistant bridges and captured report validation do not prove that all
  external clients load or follow repository instructions identically.
- Historical releases after `v0.1.0-alpha.3` still have migration reports but
  no reachable tags, so their individual baseline evidence remains weaker than
  a tag per release.
