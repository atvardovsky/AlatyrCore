# AlatyrCore 0.1.0-alpha.91

Framework `0.1.0-alpha.91`, adapter schema `74`, target templates `86`.

## Changes

- Clarified `ALATYR-TDD-001` and testing guidance: target timing and current
  authorization precede execution; module enablement and tool availability
  grant no permission. Review-first implementation remains possible only when
  the accepted mode permits it. Strict modes retain their RED requirement.
- Added nested testing `execution_contract` version 1: canonical policy and
  coverage owners, review timing/authority, command configuration, prerequisites,
  effects, environment, suite patterns, filtering and proof boundaries.
- Bound testing skill, flow, gate and evidence template to target policy;
  removed the skill's independent execution sequence and mirror-first writes.
- Added explicitly selected, digest-bound test-run records through the
  registered adapter validator, with shape-first diagnostics, count conservation,
  authorization/timing checks, current suite discovery and input freshness.
- Separated authored/discovered/skipped/blocked work from executed proof;
  metadata and mocked runs cannot establish real-persistence or end-to-end proof.
- Hardened existing test-first policy validation against malformed JSON values.
  No rule IDs were added or removed. Testing support remains optional and lazy.

## Required Target Actions

For enabled testing support, reconcile existing canonical owners before filling
the adapter's execution contract. Preserve target review gates, exceptions and
historical evidence. Refresh policy-bound surfaces and the new JSON evidence
template together. Resolve command effects, filters, configuration and suite
patterns from the actual runner without executing commands merely for discovery.
Refresh support/bootstrap projections through the normal update process.

Older adapters without the contract receive an explicit readiness warning;
schema 74 and later require it when the module is enabled. Never fabricate
approval or past runs to resolve this gap. No target project is updated here.

## Evidence Limits

Current run records bind selected tests, configuration, coverage ownership,
changed implementation inputs and result artifacts. Suite discovery uses
target-owned portable patterns over Git-visible files, not automatic parsing
of every test framework. Runner configuration and required coverage still need
repository-aware review; ignored tests/resources need explicit bindings.
`full` applies only to the declared command and proof boundary. Records do not
prove test quality, actual execution authorization, or historical RED/GREEN
ordering; those remain review obligations. No measured billing savings claimed.
