# Target-Owned Project Identity

Version: `0.1.0-alpha.103`; adapter schema `84`; target templates `98`.

The [adapter contract](../../framework/project-adapter-contract.md#target-owned-project-identity)
clarifies the existing target-evidence boundary for project names, repository
identity, support documents, worker packets, and assistant responses. Context
from another repository must not become this project's identity or facts.

## Impact And Compatibility

- Installation and update review use the same canonical identity boundary.
  Adapt the shared `AGENTS.md` identity clause while preserving target-owned rules and
  obtaining any required instruction-change approval.
- Relevant dependency/integration names, framework provenance, and legally
  required attribution remain intact. Examples use neutral labels. Historical
  evidence is not silently rewritten; corrections follow authorized redaction
  and evidence-rebinding rules.
- No installed-adapter schema, operation, parser, acceptance-validator, or
  runtime behavior changes. Framework and template versions advance for their changed content
  under the source release rules, not because of a new machine contract.
- There is no new universal project-name detector. Checks cannot prove that
  every assistant will follow the boundary or identify every external name.
- Source audits use stable opaque case IDs with private mappings/raw evidence
  outside the repository. A read-only helper checks registered literal names
  in current files and local Git history; it never rewrites or publishes.

Validation details are recorded in the companion migration report after checks.
