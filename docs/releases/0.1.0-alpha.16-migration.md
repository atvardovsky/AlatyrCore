# Alatyr Release Migration Report

This reviewed report compares the nearest reachable tagged source baseline
`v0.1.0-alpha.3` with the source tree prepared for `0.1.0-alpha.16`.
Migration reports for intervening `0.1.0-alpha.4` through
`0.1.0-alpha.15` remain part of the evidence chain. This report is source
evidence, not approval to modify a target repository.

## Adapter Contract Impact

- Framework version changed because source ownership and context routing now
  require exact registry/map identity for enabled consistency maps.
- Adapter schema version changed because installed validation now treats
  unresolved, missing, reused, or mismatched registry node references as
  structural errors and checks stale enabled-module status claims.
- Target template version changed because consistency-map schema 2 adds an
  explicit registry-sync policy and semantic routing now composes the target
  registry and map.
- The compact semantic-consistency route is measured against the existing
  profile budget. Target-owned owner evidence must not be removed to recover
  budget. Installed validation checks the combined profile and consistency
  route, not only each component in isolation.

## Migration Action Hints

- Upgrade an enabled target consistency map to schema 2 and add the exact
  `registry_sync_policy` contract from the target template.
- For every live `### Fact Type` registry entry, resolve one unique
  `Consistency map node` and make the referenced node's `fact_type` match the
  heading exactly. Additional derived nodes remain allowed.
- Change `.ai/assistant/context/consistency-routing.json` so its required
  context contains the target registry and map. Keep
  `.ai/framework/consistency-model.md` conditional for disputed relationship
  semantics, adapter repair, or conflicting evidence.
- Add or refresh the `semantic-consistency-review` context-cost scenario and
  verify the composed route remains inside target budgets. Do not silently
  widen budgets or remove owner evidence.
- Re-render `.ai/assistant/bootstrap-index.json` after the manifest, project
  map, or router changes.
- Remove unconditional live claims that an enabled module is deferred,
  disabled, blocked, not enabled, or not installed. Conditional guidance for
  genuinely unavailable states may remain.

## Residual Risks

- Exact IDs and Fact Type strings prove structural linkage, not that a target
  selected the correct owner or complete relationship graph.
- Conservative stale-wording detection cannot prove that every natural-
  language support claim is semantically current.
- Static word counts estimate repository context and do not measure hidden
  client context, model tokens, or billing.
- Historical releases after `v0.1.0-alpha.3` still have migration reports but
  no reachable tags, so their individual baseline evidence remains weaker than
  a tag per release.
