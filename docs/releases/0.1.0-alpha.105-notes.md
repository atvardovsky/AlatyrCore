# Workflow Boundary Safeguards

Framework `0.1.0-alpha.105`, adapter schema `86`, target templates `100`.

## Impact And Root Cause

Existing rules described faithful reproducers, exact coverage, safe concurrency
and publication boundaries, but declaration-level checks and optional controls
did not make their applicability evident during actual work. Green components
could attract attention away from an unresolved original effect; metadata-only
advice could hide older tooling/adoption, and repeated diagnostics could crowd
out independent blockers. The repair reuses owners rather than adding another
registry or a universal runner.

## Changes

- Named incident views expose original input/outcome, failed gate and the next
  review/adoption decision. Optional qualification is never auto-enabled and
  independent authorized work is not blocked.
- Required exact-selection/timing controls use execution schema 3. Frozen
  schema-2 policies/records remain readable; older validators reject schema 3.
  Selection uses bound request/result JSON and the same resolver in preflight
  and registered validation. Timing uses canonical resource conflicts and
  comparable observed windows; missing/overlapping evidence cannot qualify.
- `cooperation-preflight --require-clear` refuses reported conflicts or unknown
  coordination but does not reserve resources or run commands.
- `publication-preflight` compares explicit required Git files/subtrees in
  immutable source/candidate commits, including mode and dependency changes.
  It neither publishes nor replaces complete scope review, destination testing,
  current authorization, or existing closure/publication checks. Tracking-ref
  receipts use Git's literal-ref parser instead of accepting revision syntax.
- Health separates producer/installed versions, groups repetitive messages
  without changing raw blockers, and offers an explicit bounded work overview.
  Team, analysis-task and session owners remain independent and non-authoritative.

## Adoption

Use target-aware approved update and strict final verification. Preserve
historical evidence and target decisions. Propose schema-3 execution controls
only for selected commands needing them; installing templates is not adoption.
Targets normalize actual runner identities, choose qualification resources,
serialize their runners and review the complete publication scope. Older
templates/delegates need reconciliation; do not suppress migration diagnostics.

## Limits

No target application was edited or deployed. Exact identities and hashes do
not prove domain fidelity, runner honesty, peer-set completeness or live remote
state. Selected Git equivalence does not imply full-tree closure equivalence.
Default incident/team/history expansion remains off. Source validation and
migration evidence are recorded separately; no measured billing savings or
absence of every possible regression is claimed.
