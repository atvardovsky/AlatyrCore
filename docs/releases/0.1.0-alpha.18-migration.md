## Adapter Contract Impact

- Framework version changed because durable engineering evidence is now a
  portable core rule and finalization decision.
- Adapter schema version changed because installed adapters must declare the
  evidence index, record store, schema, storage policy, retention policy, and
  external-contribution boundary.
- Target template version changed because the core scaffold now supplies a
  compact index, record template, lazy context overlay, capture flow, gate,
  routing aliases, output evidence, and lifecycle guidance.
- The decision is required, but record loading and creation remain
  proportional. Small self-explanatory tasks can skip with a fact-specific
  reason; material work captures only the conclusions a fresh agent needs.
- Capturing durable evidence does not activate a change package, expand action
  authorization, approve protected work, or make historical evidence a
  canonical source of truth.

## Required Target Actions

- Run `recheck-after-framework-update` in read-only mode before applying the
  migration.
- Record current-scope authorization for adapter modification separately from
  commit, publication, deployment, or another live action.
- Migrate the core rule, manifest contract, target policy/index, routing,
  gates, operation output, and post-update evidence as one adapter repair set.
- Resolve target owners and policies for evidence storage, retention, privacy,
  and clean external contributions rather than accepting template
  placeholders as project facts.
- Preserve valid existing evidence and package links; do not overwrite target
  records while updating portable framework or template surfaces.
- Validate captured records against the shipped schema and portable target
  validator, then run target-owned checks and record unresolved validation.

## Optional Target Actions

- Import compact historical decision evidence only when provenance and
  repository binding can be established without storing raw sessions.
- Select an approved external evidence store for clean upstream contribution
  workflows that cannot include Alatyr support files in the proposed patch.

## Approval Needs

Approval needed: `target-dependent`
Approval scope: overwriting installed framework or adapter instructions and
any protected target-specific surface selected by the migration. This does not
authorize implementation, commit, publication, deployment, or live action.

## Validation Run

Source validation: framework metadata, context cost, operation, manifest,
schema, evidence scenarios, target-validator, generated-derivative, platform,
and release checks must pass before release.
Target validation: installed targets must run the portable adapter validator
and target-owned checks; source validation cannot prove the semantic truth of
a recorded invariant, hypothesis, root cause, or regression matrix.

## Residual Risks

- Deterministic validation cannot prove that the recorded reasoning is
  correct, complete, or sufficient for a specific project.
- An ignored local record is not durable team evidence unless an approved
  retained store preserves and exposes it.
- External record references can be structurally indexed but cannot be
  inspected without target-approved access.
- Existing adapters may contain local deviations or historical records not
  visible from source manifest comparison.
- Source migration evidence does not prove target validation or assistant
  compliance.

## Safety

This report is evidence only. It does not modify target files, approve
changes, complete an upgrade, authorize state-changing work, or permit private
reasoning, secrets, raw chats, prompts, or unrelated session history to be
stored as project evidence.
