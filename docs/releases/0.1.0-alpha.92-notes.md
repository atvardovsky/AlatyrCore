# AlatyrCore 0.1.0-alpha.92

Framework `0.1.0-alpha.92`, adapter schema `75`, target templates `87`.

## Changes

- `ALATYR-INTEGRITY-001`: retain per-rule behavioral authority and the original
  complaint case. Inferences, implementation and green tests cannot authorize
  new business restrictions or redefine a complaint as fixed.
- Problem model 5 and active projection 4 retain authority/acceptance state.
  Completion rejects unresolved behavioral authority and original cases.
  Existing accepted restorations may cite their original source without a new
  approval. Machine checks do not establish the truth of an authority citation.
- `ALATYR-DECOMPOSITION-001`: closed non-small tasks retain reviewed hash-bound
  model/projection witnesses. Full historical validation no longer depends on
  ignored runtime files when those witnesses exist. Active work still requires
  its live model/projection. Explicit archived schema-4/3 witnesses remain
  historical and cannot establish a new task-acceptance claim.
- Finalization, the installed delegate and upgrade verification forward current
  task ID/class, optional model selections and an explicit task-acceptance gate.
  Generic adapter health is reported as not requesting task acceptance.
- Test execution/evidence contract 2 binds credential-free resource identities,
  access and namespace isolation. The optional read-only resource planner uses
  the same conflict resolver; execution evidence retains write coordination.
- Finalization composes canonical renderers in-process under a local writer
  lock. Known output preimages/postimages support conflict-preserving rollback;
  peer edits, unrelated newly discovered files and unsafe paths are not erased.
- Aligned logical-integrity, blueprint and checklist wording with target-owned
  testing timing and authorization. Manual-review deferral is not fabricated
  RED or an automatic strict-mode exception.
- No rule IDs were added or removed. Existing gates and lazy routes are reused.
- Kept existing context/support-cost ceilings: compact machine-manifest arrays
  and compact support-state JSON preserve every parsed field without broadening
  routine context or weakening validation. Use the support-diff report for human
  file-level review; old pretty-printed states remain readable and current.

## Required Target Actions

1. Preserve local rules, user authority, original complaint sources, active work
   and historical evidence. Do not change application business behavior as part
   of this adapter migration.
2. Reconcile live models to schema 5 and projections to schema 4. Record actual
   per-rule authority, explicit applicability and original-case status; unknown
   evidence remains unresolved, never fabricated.
3. Review retention/privacy before freezing closed-task model/projection
   witnesses. The source helper `archive-task-evidence` previews outputs and
   writes only with explicit `--write` and a retention-review source. During an
   authorized cross-version update use `--migration-staging`. It does not delete
   runtime data or claim to detect all secrets. Missing original evidence blocks
   archival; do not invent it or rewrite finalized history as current evidence.
4. For enabled testing support, reconcile the canonical policy's execution
   contract and selected current run records to version 2. Resolve actual resource
   IDs, writable effects and coordination from target evidence. Preserve old run
   records as history; do not relabel them as newly observed executions.
5. Refresh the delegate, gates, flows, templates, compatibility declarations and
   generated support together. For registered task completion, pass
   `--task-id`, an independently selected `--task-class`, and
   `--require-task-acceptance` through finalization and final verification.
6. Re-run target-owned strict validation and original-case checks when
   authorized. Distinguish installation acceptance, task acceptance, product
   behavior, deployment and publication. No target repository is updated here.

## Limits

Resource identities, namespace isolation, authority citations and retention
review require honest target evidence. Cooperative file locks do not protect
against arbitrary editors, hostile filesystem races or external-service
mutations. Rollback conflicts remain explicit blockers. No measured latency,
token or billing improvement is claimed; small tasks remain lightweight and
optional testing stays lazy.
