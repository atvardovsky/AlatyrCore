# Conditional Validation And Evidence Boundaries

Version: `0.1.0-alpha.104`; adapter schema `85`; target templates `99`.

## Corrected Contracts

The current-change delegate and finalizer resolve package enforcement from
enabled target capabilities. Targets without change packages do not invent
package artifacts; enabled targets retain full package validation. Current
diff/approval bindings, exact parser syntax and full acceptance scope remain.

Selected malformed context metadata yields structured artifact/field blockers
through the API and CLI, instead of escaping as type errors. Validation stays
selected and lazy; it does not preload or schema-check an unrelated catalog.

The explicit historical-evidence index retains reviewed immutable witnesses
without applying them to current scope. Invalid/stale bindings and selected
current approvals remain strict. Historical gaps remain visible; classification
does not repair old truth, authorize changes or discharge original outcomes.

Selected-task views reuse canonical closure checks before exposing delivery
claims and retain the original incident outcome above component progress.
Wrapper/source precedence and transitive test-discovery effects remain
target-owned contracts requiring actual target verification.

## Root Cause And Prevention

Previous checks could agree across parser, dispatcher and metadata while
contradicting the canonical optional-capability owner. Happy-path fixtures did
not test selected malformed JSON before type-dependent operations. Historical
archive validation inherited the current operation's strictness, and a compact
delivery view did not reuse the full closure-owner checks.

Regressions now include independent disabled/enabled capability scenarios,
API/CLI type mutations, real Git dirty historical plans, current-approval
negative controls, invalid closure mappings, and unchanged valid routes.
No classification index is read unless explicitly selected. One immutable
validator run parses a selected classification once; normal archive coverage
is unchanged.

## Adoption And Limits

Merge the updated delegate/validation contract and regenerate target projections
under target approval; preserve stronger local rules. Historical classification
requires an explicit reviewed target index and selection through the documented
source CLI. Do not rewrite old approvals or relabel incomplete incidents fixed.
Reconcile target custom wrappers, source selectors, scratch effects and selected
case identities against their actual implementations.

These are source/adapter corrections, not target application repairs. No live
target rollout, measured real-team cost savings, or current cross-client
effectiveness is claimed. Existing evidence gaps remain explicit. Validation
and migration bindings are recorded in the companion migration report.

Cross-platform follow-up normalizes host aliases of the project root (including
macOS temporary-directory aliases) before containment comparisons. Symlinked
descendants and external file aliases remain rejected; cyclic aliases produce
findings. Fixture paths use the same canonical root as production validation.
This source-tooling correction changes no framework, schema or template version.
