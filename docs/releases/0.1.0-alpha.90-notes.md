# Alpha.90 Optimization Notes

This release reduces repeated context and tooling work without removing
authorization, owner, safety, consistency, or full acceptance requirements.

## Context Selection

Small tasks no longer load the context-discovery owner merely because the base
profile omitted it. Ambiguity, disputed ownership, failed compact evidence, and
the existing semantic/safety/approval expansion triggers remain in effect.

Architecture context supports inventory, explanation, discussion, comparison,
review, and documentation modes. All retain the canonical owner, catalog, and
flow. Missing mode selection retains the full union; modes grant no authority.
See the [architecture intent](../../templates/target/.ai/assistant/context/intents/architecture-request.json).

Context-cost reports distinguish bootstrap-only entry from session-presence
context. Scenarios include explicitly activated conditionals, but do not claim
to measure hidden client context, unobserved helper output, or billed tokens.

## Source Tooling

- Scaffold planning reuses operation-local inputs and preliminary projections.
- Approval checks reuse parsed JSON; package shards reuse measured digests.
- Source schemas use a coherent view with final mutation detection.
- Approval archive canonicalization batches file and Git-attribute work.
- Unit-suite timing feedback changes scheduling, never coverage or verdicts.
- Source refresh plans in isolation, checks dependency closure, and applies
  only changed owned outputs with explicit write authorization.
- Worker-result drafts measure actual supplied artifacts and preserve policy
  budgets, but remain review-required with no accepted obligations.

Commands, limits, and failure handling are explained in the
[source workflow](../source-optimization-workflow.md). Native provider event
hooks and automatic semantic acceptance are not supplied by this release.

## Target Update

Adapter schema `73`, target templates `85`: reconcile architecture mode context
and cost scenarios; regenerate context indexes, bootstrap/integrity, recovery
entry, and support state. Preserve project facts, local presence opt-outs, and
existing authorization. The normal target migration and acceptance gates remain
required. This source release does not automatically update installed projects.
