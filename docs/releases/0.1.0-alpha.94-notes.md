## Cause And Prevention

The version-2 change updated the executable schema, validator, templates and
introductory prose, but left a second normative paragraph at version 1. The
source checker validated policy data and required topics without comparing
the prose versions. Projection freshness only established that generated
bytes matched their inputs, not that those inputs agreed with the schema.

The existing source check now owns that comparison, so a consistent set of
generated hashes cannot hide this specific documentation mismatch.

## Target Actions And Limits

Consume the corrected framework owner and refreshed projections through the
normal reviewed update flow. Preserve accepted project testing policies,
resource ownership, authorization, timing and historical evidence. Do not
downgrade a nested version-2 execution contract or change the outer policy's
version 1 merely to match prose. No target policy migration or new test runner
is required by this correction.

This bounded consistency check does not prove every natural-language statement
or test assertion correct. No installed target project is updated by changing
the source repository.
