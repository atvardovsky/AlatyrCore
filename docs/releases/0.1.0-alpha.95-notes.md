# Bounded Context And Canonical Check Reuse

This is a source-development checkpoint, not proof of tag publication or target
acceptance. Framework `0.1.0-alpha.95`, adapter schema `77`, templates `90`.

## Changes

- Worker preparation and both evidence tiers enforce independent character
  ceilings of 12 times resolved word limits. Initial context, sibling/aggregate
  reservations, expansions, raw results, summaries and branch limits share the
  same resolver; dense text cannot evade budgets through whitespace counting.
- Stable worker instructions, visible bootstrap and selected sources precede
  variable packet/task data. Frozen expansions and authority boundaries remain.
- Source agents use a compact, derived index and one profile descriptor. Exact
  record/section projections retain digests and owner fallback; whole owners
  and changed files take precedence. Compact plans preserve readiness and
  validation; full validation alone does not make local docs/tool work large.
- Source refresh reuses canonical check results only inside one call for the
  identical complete snapshot and isolated index. Checker mutation is rejected.
  No persistent cache, inferred sparse dependency map or relaxed acceptance.
- Analyze, Plan, Apply and Verify phases prevent whole repair flows from being
  invoked during read-only analysis. Bound evidence may be referenced once,
  but approval, checkpoint, closure and publication roles stay distinct.
- The existing benchmark coverage suite adds incident and delegated-context
  tasks. It remains unexecuted coverage, not a claim of effectiveness.

## Target Migration

Refresh affected framework owners, worker tooling and target change flows using
the target's approved update process. Reconcile active context/result artifacts
against the current limits. Preserve historical evidence bytes and original
contract identity; do not rewrite history, fabricate measurements, or relabel
old receipts as current acceptance. Return blocked or narrow/reallocate context
within portable ceilings when active evidence exceeds its budget.

No JSON record shape changes. Schema `77` records tighter installed acceptance
semantics. Module enablement, authorization, protected approval, test execution,
global review and final validation are not weakened. Existing target facts and
local deviations remain target-owned.
