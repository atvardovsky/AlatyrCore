# Alatyr Release Migration Report

This reviewed report compares the nearest reachable tagged source baseline
`v0.1.0-alpha.3` with the source tree prepared for `0.1.0-alpha.11`.
Migration reports for intervening `0.1.0-alpha.4` through
`0.1.0-alpha.10` remain part of the evidence chain. This report is source
evidence, not approval to modify a target repository.

## Adapter Contract Impact

- The installed core framework pack adds `capabilities.json` as the canonical
  optional-module closure contract.
- Adapter manifests are schema-checked in source validation and target
  validation uses one line-aware YAML parser.
- Enabled modules must satisfy catalog dependencies, minimum framework pack,
  rule ownership, installed framework files, target adapter files, and mapped
  deterministic source checks.
- Framework baseline and missing migration evidence are blocking findings by
  default unless the target records an accepted deviation or severity policy.
- A diff base plus explicit approval records activates strict changed-path
  scope enforcement automatically.
- Context cost evidence classifies only `.ai/framework` as portable. Project,
  assistant-adapter, and root instruction surfaces are target-owned context.

## Residual Risks

- JSON Schema and capability closure validate structure, not architecture,
  business rules, source-of-truth correctness, or module suitability.
- The lifecycle walking skeleton does not execute an AI assistant and cannot
  prove equivalent interpretation across assistant products.
- Static word counts are context proxies, not measured model tokens, latency,
  or billing cost.
- Historical releases after `v0.1.0-alpha.3` have migration reports but no
  reachable tags; the evidence chain is weaker than a tag for every release.
- Existing targets may contain local deviations that must survive update.
