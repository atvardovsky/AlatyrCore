# Alpha.100 Audit Repairs

This is a source-development checkpoint, not a published release tag.
Framework version: `0.1.0-alpha.100`; adapter schema: `82`; templates: `95`.

## Fixed

- Focused unit-test selection tracks coverage for every changed tool. Adding
  an unrelated test or a separately covered tool cannot remove the full-suite
  fallback for an uncovered tool. Equivalent relative path spellings use the
  same routing; escaping paths fail closed. Import discovery still uses one
  cached graph.
- Concrete runtime observations reject unresolved evidence references and
  identifiers, including placeholder-only values. A missing claim identifier
  produces a finding instead of becoming a synthesized valid identifier.
- Canonical validation commands check path values parsed by the shipped
  delegate. Both `--option value` and `--option=value` reject machine-local
  POSIX, Windows, UNC, and home-relative paths. Argument syntax, required bindings, and
  duplicate-option handling remain owned by the existing parser and contract.
- The target gate checklist defers only bootstrap-verification sources, not
  task-selected canonical owners or other required profile context.

## Target Actions

On an approved update, retain target facts and local validation ownership.
Replace unresolved runtime references or identifiers with actual evidence, or
report the observation as blocked; never fabricate evidence. Use target-relative
paths in validation commands and revalidate affected contracts. Reconcile the
full gate checklist with its canonical context-profile owner and refresh
derived support projections through the existing update workflow.

No record-shape schema or rule ID changed. The adapter schema advances because
previously accepted invalid values now fail validation; the template version
advances for the gate clarification and derived projections. No target update
was performed by this source change.

## Evidence Limits

The regressions cover malformed values, option-form parity, valid controls,
real-Git registered runtime validation, and changed-file combinations.
They do not prove domain correctness or universal assistant compliance.
The human README changes add no runtime capability or measured cost claim.
The reviewed static cost baseline adds five words and 63 characters only to
three conditional/full-candidate context unions because of the clarified gate.
Routine selected context and all configured ceilings remain unchanged; these
counts are not billed-token or latency measurements.
