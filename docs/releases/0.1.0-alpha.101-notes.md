# Alpha.101 Incident Repair Qualification

Source-development checkpoint, not a published tag. Framework:
`0.1.0-alpha.101`; adapter schema: `83`; templates: `96`.

## Changes

Optional repair-review schema 2 extends the existing canonical testing policy,
not another incident registry. Target-owned assertions bind actual scenario,
branch, topology or prerequisite observations to bounded digest-verified JSON
run artifacts. Control observations distinguish a measured experiment from a
changed filename or copied label. Diagnostics can legitimately fail while
qualifying repair; only current original-flow acceptance closes an incident.
Pointer syntax uses a non-ambiguous expression with a bounded subprocess
regression for malformed repeated separators; invalid input must not trigger
exponential schema backtracking.

Optional performance policies compare median finite samples with target-owned
units, runtime/workload/instrumentation conditions and spread/regression budgets.
Captured baseline runs and policies have a measurement-only role. They cannot
become current acceptance or erase prior whole-flow failures. These checks do
not prove causal truth, observation authenticity, statistical confidence or
production performance.

The existing incident frontier now links canonical task models, owners and
completion evidence. Links are advisory, not freshness-validated conclusions.
No new mutable status registry, monitoring service or universal test runner is
introduced. Ordinary paths do not load scenario artifacts or historical logs.

## Target Migration

Preserve absent, disabled and deferred repair review and schema-1 evidence.
Installing an authoring template is not adoption. Propose schema 2 only when
target owners accept real behavioral commands, scenario/control assertions and
artifact production. Adapt `repair-qualification.json`, policy-bound flow,
gate and skill together. Refresh active evidence when required, but never
invent observations or rewrite historical failed records. Preserve review-first
execution timing, current-scope authorization and independent authorized work.

Assess four states separately: source availability, installed surfaces, enabled
target policy and exercised current evidence. An AlatyrCore source check proves
none of the target runtime's readiness. No target update, commit or publication
is implied by this implementation.
