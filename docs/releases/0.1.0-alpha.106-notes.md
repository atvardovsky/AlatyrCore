# Alpha.106: Generated Record Roles And Owner Traceability

## Repairs

Team task discovery treated every JSON file as a task, including navigation
created by the canonical finalizer. Discovery now shares the catalog-owned
filename and excludes only that reserved artifact. Catalog validation still
rejects malformed navigation; ordinary invalid task records remain errors.

Vocabulary validation checked a resolved owner name but not its referent.
Data links now require an existing, safely contained target-relative owner
file. URI/provider schemes are explicitly unsupported as direct owners; use a
local owner document retaining external evidence. File existence does not
establish semantic authority or fragment validity. No source is fetched.

## Why Existing Checks Missed This

Module fixtures did not combine real default-layout task records with the
finalizer's generated directory index. Vocabulary negative cases covered record
shape and cross-record IDs, not a missing owner behind otherwise valid metadata.
That allowed component-level success to stand in for cross-module acceptance.

The retained regression uses real Git scope and approval, the installed delegate,
canonical finalization, and acceptance/full/full validation. It requires a valid
baseline, missing-owner failure as the only structural error, restored acceptance,
and catalog-owned rejection of corrupted navigation. Adversarial cases also cover
malformed task fields, vocabulary lists and link identities. The same suite is
selected by portable CI, not just isolated helper tests.

## Target Actions

- Refresh affected framework and flow guidance without overwriting task records.
- Keep task IDs and directories; reserve `context-index.json` for navigation.
- Repair missing, escaped or unsupported data-link owners before acceptance.
- Run canonical finalization and scoped full validation after migration.

Framework alpha.106, adapter schema 87 and templates 101 record stricter reference
acceptance and aligned guidance. Record shapes are unchanged. No new bootstrap
files, historical task scans or owner-content loading are introduced. Validation
adds file-state checks only for the enabled vocabulary module's declared links;
this is not a measured claim of real-team speed, token or billing savings.
