# Incident Evidence Quality

Framework `0.1.0-alpha.98`, adapter schema `80`, templates `93`.

## Changes

- Optional `repair_review` schema 1 extends the existing canonical testing
  policy. It selects current task/path records, target full end-to-end commands
  and the existing required `repair-evidence-review` proof obligation. Selected
  incident validation reuses actual canonical execution records and their
  source/policy/input hashes. Model hypotheses retain statement ownership.
- Repair reviews retain the original case, competing hypotheses/falsifiers,
  reviewed fixture boundaries, classified attempts and diagnosis references.
  Repeated acceptance after failure requires a discriminating diagnostic
  reference; renaming the same failed output does not qualify. Missing full
  target acceptance and unknown fidelity cannot establish incident completion.
  Attempts bind run bytes and observed timezone-aware windows. Selected current
  acceptance failures cannot be omitted or reordered. Historical failures use
  captured policy/output bindings, never current-source freshness or old passes.
- Opt-in doctor frontiers navigate existing headers while retaining active
  ancestors and declared failures. No task or proof duty is retired.
- Upgrade impact can reconcile an explicit baseline report using exact finding
  multiplicities and compatible complete report/source/configuration bindings.
  Inherited blockers remain blockers; unknown comparison remains unknown.

## Target Update

Preserve current policy, historical evidence, failed tasks and explicit opt-outs.
Assess optional repair review with the target owner; do not infer full-flow
commands, applicability or authority. Legacy policies without the optional block
retain their existing execution behavior. Captured incident obligations may not
be removed or deferred into successful acceptance. Retain immutable history;
record new current evidence rather than rewriting old tests or approvals.

Problem-model, active-task, test execution and closure schema versions are
unchanged. The adapter version records opt-in stricter selected-task validation;
the test contract gains separate version-1 repair definitions, not a silent
execution-schema version change. Existing short tasks do not create repair
records or load incident history.

## Limits

Deterministic validation checks relationships, current inputs and declared
coverage. It does not prove causality, reviewer identity, actual test authenticity,
timing stability or agent obedience. Primary review must reject meaningless
falsifiers, non-applicability or diagnostic observations. Frontier/reconciliation
views grant no approval, execution authority, acceptance or validation exemption.
