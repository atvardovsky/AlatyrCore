# Selected Task State Delivery

Conditional detail of [orchestration](large-task-orchestration.md) and
[evidence](engineering-evidence.md). Load for adopted readiness or named-task
reconciliation, never routine bootstrap; existing rules remain authoritative.

## Current Disposition

Narrative reports are time-bound evidence, not a second current-state registry.
When later validation, publication or closure changes a disposition, link prior
reports from the registered current record. Preserve digest-bound historical
bytes; do not insert a pointer into an immutable report or rehash it as current.
Read that bound disposition before resuming work. Provisional finalization remains
provisional after publication; a closure is not proof of current runtime state.

`doctor --current-task <registered-id>` selects a bound model/closure, not report
history. Invalidated inputs clear affected claims. Templates, adopted policy and
exercised evidence remain distinct; availability grants neither permission nor
proof. Use canonical closure/owner checks before exposing delivery claims.
Lead incident views with original input/outcome, required obligations, failed gate,
rejected mechanisms and repair-control adoption. Component progress must not
replace an unresolved original case or the next causal experiment. Reuse canonical
execution/repair checks, including expected-negative outcomes. Diagnostics do not
establish acceptance. Before another repeated/escaped repair, review fixture
initial state and a falsifying observation. Absent optional controls need approval,
not silent adoption or blocking unrelated work. Without tooling, inspect the bound
model/closure and report machine verification unperformed; no command is mandatory.

Opt-in schema-2 task indexes may retain owner-reviewed `historical-evidence-missing`
dispositions with exact original registration, search, dependency and unresolved
outcome witnesses. Loss grants no execution, closure or acceptance. Active
transitive dependents and current/selected or complete packages cannot borrow
historical exceptions; unavailable committed retention evidence fails closed.

Bind optional checkpoints in `analysis_evidence.selected_context`: at most 16
exact `{path, sha256}` rows. Publish model/projection/header together. Selected
health exposes references, not content; stale bytes clear advice. Hashes prove
neither meaning, execution nor authority. Reconcile at phase boundaries, preserving
failures; no second registry, newest-file selection or narrative preload. Handoff
retention remains explicitly reviewed, never automatic private publication.

## Declared Readiness

Schema-6 models may explicitly adopt `execution_dependencies`: one
`{obligation_id, requires}` row per proof obligation, including empty prerequisites.
The shared resolver rejects cycles, unknown/duplicate IDs, incomplete coverage
and settled obligations with unresolved prerequisites. Ready/blocked/waiting
views retain all unresolved duties; partial blocks must not hide independent work.
Passed/waived dependency statuses remain declarations, not newly verified evidence.
Omit the mapping when not adopted. Never infer it from prose or task predecessors.
The active projection preserves adopted mappings within existing byte/word limits.

## Execution Focus

Derive selected-task orientation from validated model/readiness/advice, not
another status file. One snapshot binds task ID, model digest, objective, scope,
unresolved duties and proposed probe. Proposals name obligation, uncertainty,
method and completion condition; they are not commands or authorization.

Separate ready, blocked, waiting and dependency-unconfigured probes. Unknown
mappings neither require adoption nor establish readiness. Staleness clears
affected readiness/advice; only explicit dependency and artifact mappings can
preserve independent work. Shared/unknown scope blocks actionable advice.
Retain duties. Overflow returns references without actions
or truncated constraints. Closed tasks remain historical, with no active work.

Re-anchor for changed requirements, contradictory evidence, scope expansion,
failed gates, recurring repairs, worker convergence and continuity boundaries.
Before continuing/answering, review newest intent, owner/projection and affected
obligations through the authorization owner's request brief. Pending revisions,
invariant conflicts, failed gates, inconclusive probes and original-case status
are review signals, not incident detection or global freezes. Unchanged failed
attempts need a discriminating question/input or explicit retry rationale;
command counts prove no drift. Probe/prior-result digests locate the reviewed
question/observation, not proof of review. Question-bound routing selects that
explicit obligation, never silently the first recommendation.

Preserve every requested outcome across supporting scopes, workers and publication.
Preparation is not delivery. A local blocker stops only dependent work. Partial
handoffs name remaining outcomes and blockers/next actions, never replacing the
parent request or requiring already-granted approval again.
For repeated/costly work, distinguish useful evidence from activity using the
[existing delivery history](test-execution-selection.md#delivery-efficiency).
Keep original obligations visible while batching supporting work or releases;
budget exhaustion means reassessment, never reduced acceptance.

Use verified hooks/controlled executors for pre-action checks; otherwise check
procedurally and report no interception. No universal hook, intent parser,
context eviction or permission is implied. Do not preload the corpus, growing
summaries or routine-bootstrap focus. Evaluate behavior with the
[drift protocol](effectiveness-metrics.md#execution-drift-evaluation), separately
from record/projection tests.

New installs default to non-blocking procedural/observe lifecycle delivery;
native setup belongs to approved project-local installation scope. Updates
preserve settings and absent policy; unverified clients use procedural checks.
Delivery reuses these owners. Requests revoke bindings;
synthetic continuation grants no authority. Bound reminders, preserve
interruption against delayed callbacks, never reopen closed scopes. Preserve
native definitions/trust/opt-outs; distinguish
configuration, exercised interception and procedural fallback.

Optional request guards follow request reconciliation and the lifecycle flow;
partial answers remain distinct from canonical completion.

### Terminal Action Prerequisites

Schema-3 `terminal_control` schema 1 optionally binds 1..16 phase/effect rules:
required proof, command, canonical receipt, distinct real candidate/effective
environment artifacts and freshness limit (1..86400 seconds).

Matching commit/publish/live-external review requires a passed proof citing the
receipt, current task/request/command identity, terminal `passed`/integer exit 0,
ordered nonfuture timestamps, exact current inputs and intact result artifact.
Running, failed, interrupted, waived or unrelated evidence cannot unlock work.
Select by phase/effect, not convenient outcome subsets. Polling is not completion.

Retain consumed artifacts in the baseline and original `brief_sha256` in mutation
actions. Rebinding may refresh receipt selection/hashes, never adopted policy;
queued actions cannot inherit refreshed candidates. Null/absent control reads no
prerequisite artifacts. Inspection, independent effects, settled work and existing
readiness/authorization/acceptance remain unchanged. Only consuming callers are
blocked; native/non-bypassable enforcement needs verified client/project setup.

## Request-Bound Work

Schema-3 briefs add nullable `focus_control`: null preserves ordinary behavior;
`dependency-readiness` adopts existing model `execution_dependencies`. Schemas
1/2 remain readable; no automatic adoption, TDD conversion or extra bootstrap.

Adopted actions carry `brief_sha256`, lowercase SHA-256 of exact reviewed bytes.
Work names 1..32 unique `obligation_ids` from selected outcomes' proof roots or
transitive prerequisites, never unrelated branches or reversed edges.
Modify/live-external work requires canonical declared readiness. Inspection may
examine blocked/waiting duties. Commit/publish keep separate authority, without
requiring already-passed proofs to become ready again. Completion requires every
original outcome's proofs passed, not waived; readiness grants no permission.

Bind before dispatch; preserve worker-original request/task IDs and brief digest
at convergence. Never retag stale results. Reconcile affected work after changed
intent/context, preserving unaffected evidence. Shared review checks declared
bindings, not dispatch authenticity or semantic relevance. Source-first review
and drift evaluation remain necessary.

Ordinary review separates evidence readiness from declaration consistency using
canonical artifact verification. Shared/unscoped staleness, incomplete verification
or diagnostic overflow require task review. Scoped failures gate affected
proof/prerequisite closures and direct writes across modify/commit/publish/live
actions. Preserve read-only recovery and explicitly independent work; absent
dependency mappings prove no independence. Completion retains canonical checks.
Missing optional capture remains unverified.

Review progress covers every brief outcome, not just action IDs. Completion
callbacks retain partial outcomes as unfinished/handoff review within existing
reminder limits. Declarations prove neither source coverage nor dependency
necessity; challenge both before capture/revision.

Checkpoint validity, response termination and task acceptance are separate.
Empty readiness requires handoff review, not success. Terminal review reuses
canonical completion/closure checks: current result bindings, original outcomes,
obligations and reviews. Retain actual closure and authoritative archived
projection in selected context. Completion-only binding may inspect closed work,
never execute/reopen it or grant acceptance, publication or runtime readiness.
Requests/end revoke pending continuation before waiting on slow checkpoint locks;
interruption/freshness still win at delivery.

## Outcome Qualification

Before implementing or designing tests for material multi-boundary changes or
recurring repairs, capture requested surfaces and rejected substitutes.
Reuse request outcomes and required model proofs; do not create another task
registry. Local checker success is component progress, never canonical selected-task
acceptance. Reconcile remaining duties before stopping or reporting completion.

Schema-7 `analysis_evidence` optionally adopts 1..16 `outcome_checks`. Each names
the source, hash-bound oracle, expected result, rejected substitute, required
proof IDs and exact actor/system/entrypoint/conditions/surfaces. Request review
matches captured IDs, expectation, substitute and proofs to the current brief.
Missing capture stays a disclosed procedural gap; never infer complete request
coverage from mutually agreeing declarations.

A nullable observation binds the case digest, actual scope, exact evidence class,
decisive-check reach, status, surface digests and result artifacts. Classes are
`source-review`, `component-execution`, `original-case`, and `native-client`;
none substitutes for another. Passed proofs and completion need a supported,
scope-matching observation whose decisive check was reached. Characterizing a
deficit, fixture timeout, wrong backend or post-boundary injection cannot prove
the requested outcome. Unverified observations remain valid progress when their
proofs stay open. Expected safe rejection may be a successful outcome without
claiming the larger repair complete.

Capture cannot silently disappear or change. Successors retain checks;
supersession needs a bound JSON owner decision matching exact before/after case
digests, preserving IDs/history. Archive immutable oracle/results; historical
verification excludes current implementation inputs. Sources and artifacts use
the existing shared byte limits and freshness checks; overflow blocks evidence,
not permission to truncate it. Projections expose derived qualification, not a
bare supported label. Omitted controls keep their no-additional-read path.

Checks validate recorded declarations/bytes, not execution, authority or semantic
truth. Independently challenge the original-request oracle; observe native
interception and real-agent behavior separately. Configuration, fixtures and
hashes do not guarantee compliance.

## Selected Document Warnings

During consistency routing, exact selected documents also select their reviewed
stale-document warnings. For profile-only discussion, explicitly request
`context-plan --document-warnings`; do not fabricate changed paths.
Retain canonical graph, owner, structured-finding and digest checks. Review inputs
must neither recursively select other warnings nor promote relationships.
Do not perform this additional lookup for unrelated default tasks.

## Independent Work Views

An explicit work overview links the analysis-task index, reported team claims
and session-cooperation entry point without merging owners or statuses. Empty
team claims do not imply no active analysis tasks. Missing, invalid or stale
views remain unknown; a recorded date is not a liveness guarantee. Load these
bounded headers only for a coordination question, not ordinary bootstrap.
