# Selected Task State Delivery

Conditional guidance delegated by [large-task orchestration](large-task-orchestration.md)
and [engineering evidence](engineering-evidence.md). Load for adopted dependency
readiness or reconciliation of named-task disposition, not routine bootstrap.
Existing canonical authorization, evidence and acceptance rules remain unchanged.

## Current Disposition

Narrative reports are time-bound evidence, not a second current-state registry.
When later validation, publication or closure changes a disposition, link prior
reports from the registered current record. Preserve digest-bound historical
bytes; do not insert a pointer into an immutable report or rehash it as current.
Read that bound disposition before resuming work. Provisional finalization remains
provisional after publication; a closure is not proof of current runtime state.

With canonical tooling, `doctor --current-task <registered-id>` selects one bound model/closure
without scanning historical reports. Invalidated inputs clear derived claims.
Installed templates, policy adoption and exercised evidence remain distinct;
availability and declared checkpoint passes grant neither permission nor proof.
Selected closure views must use canonical closure/owner checks before exposing
delivery claims. For incident work, lead with the bound original outcome,
required obligations, failed gate and rejected mechanisms. Component progress
must not replace an unresolved original case; these views remain declarations,
not fresh runtime verification or a substitute for the next causal experiment.
Reuse canonical selected execution/repair validation, including expected-negative
outcomes. A consistent diagnostic record does not establish incident acceptance.
For repeated or escaped incidents, the selected view also exposes the original
input, terminal outcome, failed gate and repair-control adoption decision before
another related patch. Request approval to adopt absent optional controls;
never silently enable them or block independent unrelated work. Review fixture
initial state and a falsifying observation, not only green component totals.
Without that tooling, inspect the bound model/closure manually and report
machine verification as unperformed; no portable runtime command is required.

## Declared Readiness

Schema-6 models may explicitly adopt `execution_dependencies`: one
`{obligation_id, requires}` row per proof obligation, including empty prerequisites.
The shared resolver rejects cycles, unknown/duplicate IDs, incomplete coverage
and settled obligations with unresolved prerequisites. Ready/blocked/waiting
views retain all unresolved duties; partial blocks must not hide independent work.
Passed/waived dependency statuses remain declarations, not newly verified evidence.
Omit the mapping when not adopted. Never infer it from prose or task predecessors.
The active projection preserves adopted mappings within existing byte/word limits.

## Execution Focus

For a selected active task, derive orientation from its validated model and
existing readiness/advice, not another mutable status file. Bind the task ID,
model digest, objective, scope references, unresolved duties and proposed probe
to the same snapshot. A proposal names its obligation, uncertainty, method and
completion condition; it is not an executable command or authorization.

Keep ready suggestions separate from blocked, waiting and dependency-unconfigured
probes. Unknown mappings do not require adoption and never establish readiness.
Stale selected artifacts clear actionable readiness and advice together, while
retaining unresolved duties. A bounded focus overflow returns references and no
action, not truncated constraints presented as sufficient context. Closed task
views remain historical and propose no active work.

Re-anchor at changed requirements, material contradictory evidence, scope
expansion, failed gates, repeated unresolved repairs, worker convergence and
continuity boundaries. Review the newest intent, selected owner/projection and
affected obligations before the next state change. Existing pending revisions,
invariant conflicts, failed gates, inconclusive probes and original-case status
are signals, not a new incident detector or global freeze on independent work.
An unchanged failed attempt needs a new discriminating question, input or
explicit retry rationale; a command-count timer is not evidence of drift.
The proposal's probe digest and prior-result digest locate the exact question
and observation for primary selection/retry review; they do not record that
the review occurred. A question-bound context route selects that same explicit
obligation, never silently the first recommendation.

Use verified host hooks or a controlled executor for pre-action checks when
available; otherwise perform the same checkpoint procedurally and report that
execution was not intercepted. No universal hook, conversational-intent parser,
context eviction or permission grant is implied. Do not reload the full corpus,
repeat a growing summary, or add focus to routine bootstrap. Evaluate actual
agent behavior using the [drift comparison protocol](effectiveness-metrics.md#execution-drift-evaluation),
separately from deterministic record and projection tests.

## Selected Document Warnings

During consistency routing, exact selected documents also select their reviewed
stale-document warnings. For profile-only document discussion, explicitly request
`context-plan --document-warnings`; no fabricated changed paths are needed.
Canonical graph, owner, structured-finding and digest checks remain required.
Review inputs never recursively select other warnings or promote relationships.
Unrelated default tasks do not perform this additional lookup.

## Independent Work Views

An explicit work overview links the analysis-task index, reported team claims
and session-cooperation entry point without merging owners or statuses. Empty
team claims do not imply no active analysis tasks. Missing, invalid or stale
views remain unknown; a recorded date is not a liveness guarantee. Load these
bounded headers only for a coordination question, not ordinary bootstrap.
